# 内存提醒

原生 macOS 菜单栏应用，使用 AppKit、SwiftUI 和系统进程接口，无第三方依赖和网络请求。支持 macOS 13 及以上；在本机架构上编译。

## 使用

点击菜单栏的内存芯片图标，查看系统内存压力和建议退出的应用。默认只显示候选应用，勾选“显示全部”可查看本次监测到的普通桌面应用及其内存占用。点击齿轮可调整阈值、管理忽略名单和登录启动。

菜单栏弹出窗口按所在屏幕的可用区域限制尺寸，应用列表滚动显示。屏幕高度较小或结果文字较长时，整个内容区也可滚动，确保顶部和底部控件可访问；打开时会校正窗口位置，防止超出屏幕边缘。

默认规则如下：

- 每 15 秒读取一次系统状态；内存压力持续偏高或严重至少 2 分钟后，才会自动提示。
- 应用至少 30 分钟未切到前台，且可归属进程的内存合计至少 500 MB，才进入候选名单。
- 自动提示以浮动小窗出现，不抢占当前应用的前台焦点。用户点击“查看应用”后，可选择一个或多个应用，确认后发送正常退出请求。
- 自动提醒间隔为 30 分钟；“稍后提醒”使用同一间隔。没有候选应用时不会自动打扰。
- 当前前台应用、本工具、访达等受保护系统应用不会成为退出候选。忽略名单按应用标识符保存。
- 唤醒或重新登录会话后，重新计算闲置时间和内存压力持续时间。暂停自动提醒后仍可查看实时数据；重新启动应用会恢复提醒。

菜单的“更多”中提供提醒效果预览。预览只展示界面，不会改变内存压力、修改筛选规则或退出其他应用。

## 统计和退出边界

内存压力优先读取 `kern.memorystatus_vm_pressure_level`（1 正常、2 警告、4 严重），同时订阅系统 memory-pressure 事件。若当前状态和事件均不可读，会显示“暂不可读”，不会将未知状态当作正常或触发提醒。压力指标与活动监视器对应同类系统信号，但活动监视器图表存在采样和平滑差异，不能保证每个瞬间颜色完全一致。

应用内存使用 `proc_pid_rusage` 的 `ri_phys_footprint`，按应用包路径及进程父子关系合并；每个进程只计算一次。独立桌面应用不会被重复归入启动它的另一个应用。不可读取的进程会被标记，无法归属的系统/XPC 服务不强行计入。共享内存、压缩记账和采样时点会使合计值与活动监视器有所差异；这个数值不是退出后可立即释放的保证值。

闲置时间从本工具启动后开始记录。已有应用会从零开始，不会推测启动前的使用记录；应用一直留在前台时不计为闲置。长时间没有切到前台，也可能正在下载、同步、通话、播放媒体或执行任务，因此仍需用户审阅。建议将这类长期运行的应用加入忽略名单。

退出使用 `NSRunningApplication.terminate()`，不执行强制终止。确认后会再次检查应用身份、启动时间、前台状态及忽略名单，防止进程 ID 复用或候选状态变化导致误操作。应用可以弹出保存提示、延迟退出或拒绝请求；界面会在 5 秒后核对实际退出情况。后台任务、未保存内容与普通手动退出具有相同影响。

工具不申请管理员、辅助功能、屏幕录制或完全磁盘访问权限。提醒使用本地小窗，不依赖通知中心权限。配置和忽略名单通过系统 UserDefaults 保存在 `com.samuelzhao.memory-guard-menu` 域；激活记录仅在进程内存中保存，不上传、不写历史文件。

## 构建、安装与移除

在此目录运行：

```sh
zsh build.sh
zsh install.sh
```

构建产物为 `build/内存提醒.app`。安装脚本将其复制到 `~/Applications/内存提醒.app` 并打开。已有同标识符版本时，会先在项目的 `backups/` 下备份，再正常退出旧版并更新；如遇其他同名应用则停止。签名为本地 ad-hoc 签名，未做 Developer ID 公证。

登录自启动默认关闭；在设置中开启后由 `SMAppService.mainApp` 管理。系统可能要求到“系统设置 → 通用 → 登录项与扩展”确认。此开关不会安装自定义 LaunchAgent，也不会在主动退出后强制重启。

移除时，先关闭“登录时自动打开”，再从菜单中退出，将 `~/Applications/内存提醒.app` 移到废纸篓即可。源码和备份保留在本项目目录。

## 验证与诊断

`build.sh` 检查编译、应用签名和规则测试，覆盖前台切换、唤醒、进程分组、阈值边界、持续时间、冷却和忽略条件。

`zsh test-integration.sh` 会创建一次性测试应用，用独立配置验证真实进程读取、取消退出、忽略名单、确认后状态变化、正常退出及结果反馈。它只向专门的 `com.samuelzhao.memory-guard-fixture` 应用发送退出请求，不对日常应用执行退出。

```sh
# 只读输出当前压力、逐应用占用与分组数量，不退出任何应用。
'build/内存提醒.app/Contents/MacOS/MemoryGuardMenu' --status

# 启动界面，同时将最新状态写到明确指定的本地文件。
'build/内存提醒.app/Contents/MacOS/MemoryGuardMenu' --show-window --diagnostics /tmp/memory-guard-status.json

# 应用未运行时，导出浅色/深色的主界面、设置和提醒预览。
'build/内存提醒.app/Contents/MacOS/MemoryGuardMenu' --render-preview /tmp/memory-guard-previews
```

`--diagnostics` 文件包含应用名称、标识符、进程 ID 和内存数据，仅在显式指定此参数时写出。`--quit-running` 只向同一标识符的旧版本发送正常退出请求，用于更新。不要运行会制造系统内存压力的命令来测试提醒，使用菜单中的预览即可。

系统接口参考：[应用激活通知](https://developer.apple.com/documentation/appkit/nsworkspace/didactivateapplicationnotification)、[正常退出应用](https://developer.apple.com/documentation/appkit/nsrunningapplication/terminate())、[内存压力事件](https://developer.apple.com/documentation/dispatch/dispatchsourcememorypressure)。
